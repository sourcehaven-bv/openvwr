# What the system records by itself

Besides the fields that are filled in, OpenVWR captures a number of things
automatically. These matter for demonstrating accountability.

| Aspect | What is recorded |
| --- | --- |
| **Change history** | For every record, who changed what and when. Versions can be compared, including changes in linked items such as data subjects or systems. |
| **Versions and approval** | Records can be captured in a version submitted for approval to mandate holders. Their sign-off is recorded with date and person. |
| **Organisation** | Every record belongs to one organisation. Users only see the records of the organisation(s) they have access to. |
| **Users and roles** | For users, the name, email address and assigned roles are recorded. Roles determine who may read, fill in, approve or administer. |
| **Created and changed dates** | For every record and every linked item. |
| **Deleted records** | Deleted records are retained and can be restored; they disappear from the regular overviews. |
| **Import provenance** | For records taken over from an earlier register, the original provenance is retained. |

# Reuse of data

A number of items are not entered again for every processing activity, but
recorded once and then linked to several of them. That avoids inconsistent
spellings and makes it possible to see from one place where something is used.

So for a single supplier it is immediately visible which processing activities
it is involved in, and for a single system which activities take place in it.

Services and departments are an exception: each register has its own list for
those.

# Publication

Processing activities, algorithms and their related data can be published on a
public website so citizens can consult the register. Publication does not happen
automatically: per record a date is set from which publication is allowed.
Without that date the record stays internal. The system checks in advance
whether a record is suitable for publication and shows any points of attention.

DPIAs and pre-scans have no publication function: those records stay internal.
That matches practice, where a DPIA is not usually published in full.

Records can also be exported, including to PDF, for use outside the system.
